# Texel 0.3.0 기본 기능 고도화 계획

작성: 2026-10-15 (Asia/Seoul). 근거: 사용자의 MCP·스프레드시트 기본 기능 최대 고도화 요청, spec.md/designs.md/MCP_GUIDE.md, 0.2.1 소스 및 감사 수정 기록, AI_IMPLEMENTATION_DOC_STANDARD/AI_CODING_STANDARD. 실행 방식: 이 세션에서 단계별 구현·검증, 마지막 별도 읽기 전용 리뷰. Git 저장소는 없으며 원본 감사/과거 배포물을 보존한다.

## 목적과 범위

로컬 업무·데이터 분석이라는 기존 제품 목적을 유지한다. 사람이 대량 데이터를 편집·검사하고 AI가 같은 문서에 여러 변경을 안전하게 적용하는 기본기를 함께 강화한다. Assumption: 이번 요청은 두 사용 방식을 균형 있게 강화하는 0.3.0 작업이다. 기존 30개 MCP 도구와 native schema 1, 오프라인/stdio/경로 범위/revision/보호/undo 계약을 유지하는 추가 기능으로 구현한다. 일반 문서·계획은 AGENTS.md 3.5/4/13.1에 따라 구현 기준을 기록한 후 별도 승인 대기 없이 진행한다.

## 고정 계약

### F1 계산 (69 → 89 함수)

추가 20개: AVERAGEIF, AVERAGEIFS, MINIFS, MAXIFS, SUMPRODUCT, IFNA, IFS, ISNA, ISEVEN, ISODD, SIGN, TRUNC, QUOTIENT, EXACT, CLEAN, REPLACE, EDATE, EOMONTH, NETWORKDAYS, WORKDAY.

- 조건 집계/SUMPRODUCT는 같은 행·열 모양의 범위를 요구한다. 숫자 집계는 범위의 text/bool/blank를 제외하고 선택된 오류는 전달한다. AVERAGE 계열의 수치 표본 없음은 #DIV/0!, MINIFS/MAXIFS 일치 숫자 없음은 0. IFNA는 #N/A만 복구하며 IFS는 첫 true 분기만 평가하고 일치 없으면 #N/A.
- 조건 문자열의 정수는 float로 축소하지 않는다. 와일드카드는 `*`, `?`, `~` escape를 사용하며 `[` 같은 문자는 그대로 비교한다. 기존 COUNTIF/SUMIF와 복합 필터도 이를 공유한다.
- 날짜는 기존 ISO date/직렬값 정책을 유지한다. EDATE는 말일을 해당 월의 마지막 날로 보정, EOMONTH는 대상 월 말일. WORKDAY는 시작일을 제외해 평일을 이동하며 NETWORKDAYS는 양 끝 포함, 역순은 음수. 토·일/중복 휴일 제외, 날짜 순회 상한 100,000일(#LIMIT!). 일반 float 산술과 Excel 전체 날짜 호환 한계는 유지한다.

### F2 표 정리와 검색

- `sort_table(book, sheet, region, keys, header=True)`: keys 1..8개의 `{column:0-based relative, descending:bool}`. 계산값 기준 안정 정렬, 같은 키는 원래 순서, text 대소문자 무시, blank/error는 방향과 관계없이 마지막. 행 단위 값/수식/서식/메모 이동 및 상대 수식 보정. 병합과 겹치는 정렬은 거부, 변경 상한 10,000셀. 기존 sort_range 동작과 인자는 유지한다.
- `set_filter(book, sheet, region, conditions, match='all', header=True)`: 1..8개 `{column, criterion}`, match all/any, 범위 높이 최대 200,000. 행 삭제 없이 비일치 행을 숨기며 기존 단일 filter_spec를 읽는다. 새 filter_spec는 첫 조건의 column/criterion도 유지한다. 0.2.x는 첫 조건만 표시할 수 있으므로 복합 필터 편집은 0.3.0 기준이다.
- 공용 검색: 현재 시트/통합 문서, 선택 범위(선택적), raw/계산값, 부분/전체 일치, 대소문자 옵션, 빈 검색어 거부. 저장된 셀만 순회하고 결과 offset/limit 최대 2,000셀. 바꾸기는 raw에만 적용, literal 검색, 보호/유효성 및 10,000 변경 상한, 한 번 undo. 기존 find/replace MCP 도구도 유지한다.

### F3 진단

- `evaluate_formula(sheet, formula, at='A1')`: 현재 스냅샷의 원래 셀 값을 참조하는 읽기 전용 표현식 계산이다. at은 ROW/COLUMN 문맥만 정하며 원래 셀을 가리지 않는다. 원문/문서/revision/이력을 바꾸지 않고 값·타입·오류를 구조화해 반환한다.
- `trace_dependencies(sheet, cell)`: 직접 선행 범위와 후행 수식 셀, 해석 오류, 잘린 결과 여부. 모든 조건 분기의 정적 참조를 포함하고 이름 범위/다른 시트/범위를 처리한다. 간접 그래프 전체를 계산했다고 주장하지 않는다. 결과 최대 200개, 후행 검사 최대 10,000 수식.

### F4 MCP (30 → 39 도구)

기존 도구 유지, 추가: read_ranges, preview_operations, apply_operations, patch_format, sort_table, filter_table, search_cells, evaluate_formula, trace_dependencies. capabilities 리소스와 안전한 변경 계획 프롬프트를 추가한다.

- typed Pydantic 입력 모델은 현재 lock의 2.14.0을 직접 의존성으로 선언한다. 알 수 없는 필드·범위를 거부하고 schema/도구 설명에 한계를 노출한다. 기존 `{ok,revision,error}` envelope를 유지한다.
- read_ranges: 요청 1..20개, 기존 read_range와 동일한 페이지 계약, 한 스냅샷에서 응답 셀 합계 ≤2,000. 초과는 오류로 알려 호출자가 페이지를 좁히도록 한다.
- batch: 1..50개 순차 작업, write/clear/copy/fill/format/borders/sort/filter/replace/note. 전체 셀 처리량과 최종 변경 셀 각각 ≤10,000. 파일 I/O/시트 삭제/임의 코드 작업은 batch 문법에 없다. 다른 시트에 대한 변경은 지원한다.
- preview_operations는 apply와 동일한 Session 후보 검증(보호·유효성 포함)을 수행하고 파일/revision/undo를 바꾸지 않는다. 변경 셀 개수, 메타데이터 변경 여부, 최대 200개 diff(기본 50)를 반환한다. 긴 raw/note는 256자 요약과 잘림 표시로 반환한다.
- apply_operations는 expected_revision 필수, 하나의 candidate/commit/revision/undo. 중간 실패·보호·유효성·충돌이면 전체 원복. preview 이후 충돌도 apply의 CAS로 거부한다. 자동 재시도하지 않는다.
- patch_format은 제공된 필드만 바꾸며 null/누락은 유지, 빈 색 문자열은 색 해제. 기존 format_range의 전체 기본 서식 계약은 유지한다.

### F5 TUI 기본 조작

- 데이터 메뉴에 다중 열 정렬/복합 필터를 직접 노출한다. 모달에 최대 3개 열/방향 또는 조건, all/any·header를 표시한다(공용 API는 최대 8개). 80×24에서도 body 스크롤과 적용/취소 접근을 유지한다.
- Ctrl+F 검색에 raw/값·전체 일치·통합 문서 범위를 추가하고 일치 셀로 이동한다. Ctrl+H에는 raw 전체 일치·통합 문서 범위를 제공한다.
- Ctrl+방향키는 연속 데이터 끝 또는 다음 데이터로 이동, Ctrl+Shift+방향키 선택 확장. Ctrl+A는 사용 영역, Shift+Space는 전체 행, Ctrl+Space는 전체 열. 숨김/필터와 병합 앵커를 반영하며 희소 데이터의 긴 빈 구간을 셀 단위로 전부 생성하지 않는다.
- 수식 입력 F4: 커서의 A1→$A$1→A$1→$A1→A1 순환, 문자열/시트 이름을 참조로 오인하지 않는다. 선택한 수식 범위 내 참조도 처리한다. 수식 진단은 명령 메뉴에서 접근한다.
- 새 UI 문자열은 한국어/영어로 제공한다. 메뉴/키보드/마우스→공용 도메인→저장→undo까지 검증한다.

## 공식 근거와 한계

[MCP SDK tools](https://github.com/modelcontextprotocol/python-sdk/blob/main/docs/servers/tools.md)의 모델 인자·schema 방식을 설치된 MCP 2.3.0과 대조했다. 함수 의미는 Microsoft의 AVERAGEIFS/SUMPRODUCT/EDATE/EOMONTH/NETWORKDAYS/WORKDAY 공식 문서를 참조하되 위 숫자/날짜/오류 계약과 실제 검증을 기준으로 한다. 추가 클라우드 연결, 계정/인증, VBA/전체 Excel 객체, 사람의 IME/다른 OS/장시간 검증은 이번 구현의 완료 주장에 포함하지 않는다.

## 실행 기록

Windows native에서 복합 필터의 Tab 이동과 문자를 같은 패킷으로 보냈을 때 Tab binding의 지연 처리로 문자가 이전 필드에 도착했다. F5 키보드 문맥 일관성 범위로 포함한다. FormDialog의 Tab/Shift+Tab을 우선 binding으로 처리해 포커스 전환 이후 키가 새 필드로 가게 하며, 실제 App 키 큐 회귀와 native 재실행으로 확인한다. 초기 native 출력은 보존한다.

설치본 검증에서 evaluate_formula의 기본 at=A1이 SUMPRODUCT(A1:A2,...)의 원래 A1을 가려 #CYCLE!을 만들었다. 읽기 전용 표현식 평가의 목적에 맞게 F3 계약을 정리했고, at은 ROW/COLUMN 문맥만 제공하도록 수정했다. expression_red→expression_green(관련8개) 및 source_final_check로 원본 값 참조를 검증했다.

별도 읽기 전용 리뷰 3건: 바꾸기 출력의 할당 전 길이 검사, SUMIF 공통 집계 계약 적용, WORKDAY 정확히100,000일 완료 경계. review_red의 4 failed → 관련89 passed로 닫았다. 전체 행/열 선택의 기존10,000셀 편집 상한과 복사의 기존 validation 복제 계약은 그대로 유지한다.

S1: 신규 함수 RED 39 failed → 함수/기존 수식/회귀 89 passed. S2: 모듈 미존재 RED → 표/함수/기존 편집·모델 52 passed. S3: 모듈 미존재 RED → 진단·이동·함수 43 passed. S4: 모듈 미존재 RED → batch/기존 저장·편집 13 passed. S5: 신규 도구 부재 RED 3 failed → MCP 신규/기존 및 실제 stdio 6 passed. SDK annotation snake_case 및 반환 is_error 확인의 harness 가정을 교정했다. S6: 신규 조작 부재 RED 4 failed → 신규·기존 TUI 29 passed. 로그는 evidence_0_3_0에 보존한다. 모듈 미존재 RED를 동작 assertion 실패라고 주장하지 않는다.
