# Texel 0.3.0 구현·검증 결과

작성: 2026-10-15 (Asia/Seoul). 근거: 사용자 기본 기능 고도화 요청, [작업 기준](0.3.0-plan.md), 현재 소스/테스트, 독립 읽기 전용 리뷰, Windows 입력 및 배포 검증 기록. Python 3.15.0 / Textual 8.2.8 / MCP 2.3.0 / Pydantic 2.14.0. 사용자 OS 언어를 탐지했다고 주장하지 않으며 기존 한국어 문서·한/영 UI 정책을 따른다.

**완료: F1~F5 구현과 S1~S8 검증을 마쳤다. 전체298개 테스트·Ruff, 소스/portable Windows 입력, wheel/portable 자체 실행 및 제품37개 모듈의 파일 일치 검증을 통과했다.**

기존 30개 MCP 도구 이름·기본 인자와 native schema 1 읽기를 유지한다. 구버전은 복합 필터의 첫 조건만 표시할 수 있다. batch의 전체 셀 처리량/최종 변경 셀은 각각10,000, 최대50작업, preview는 보호/유효성을 포함해 검증하되 파일/revision/이력을 변경하지 않는다. apply_operations는 clear/replace를 포함하므로 destructive_hint=true로 정확히 표시한다. read_ranges는 최대20요청·합계2,000셀의 단일 스냅샷이다.

## 재현과 검증 이력

- 계산 신규 RED 39 failed → 신규/기존 수식·회귀 89 passed.
- 표/진단/batch는 모듈 미존재 수집 실패를 먼저 확인한 뒤 각각 관련52/43/13개 테스트가 통과했다. 수집 실패를 실제 동작 assertion RED로 과장하지 않는다.
- 새 MCP 부재 RED 3 failed → 기존/신규 MCP 6 passed. 실제 stdio batch→SQLite 저장→실행 중 TUI 관찰→undo와 충돌 거부를 포함한다.
- 새 TUI 부재 RED 4 failed → 신규/기존 TUI 29 passed. 80×24/100×30의 실제 적용 버튼과 원문/DB 결과를 대조했다.
- 독립 리뷰의 세 발견(바꾸기 할당 전 상한, SUMIF 공통 정책, WORKDAY 정확한100,000일 경계)은 review_red의4 failed → 관련89 passed로 수정했다. 전체 최대1GB 치환은 실행하지 않았고, 약33.6MB의 작은 재현 및 수정 후2MB 미만 상한 테스트를 사용했다.
- 소스 설치본 검사에서 임시 셀 대체로 생긴 #CYCLE!을 발견해 F3를 읽기 전용 표현식 문맥으로 명확히 했다. expression_red1 failed → 관련8 passed, source_final_check 통과.
- Windows의 결합 Tab+문자가 이전 필드에 도착한 문제는 App 입력 큐 회귀로 재현했다. 우선 Tab/Shift+Tab의 정확한 app action namespace로 수정해 관련 TUI32개 및 실제 native 입력이 통과했다. 초기 native_source_initial.json과 tab_red/tab_green의 실패도 보존한다.
- MCP schema 테스트의 snake_case annotation 및 도구 오류가 예외 대신 is_error로 반환되는 부분은 설치 SDK를 읽고 harness를 교정했다. 제품 실패와 구분한다.

현재 실행 로그는 `docs/upgrades/evidence_0_3_0/`에 있다. 마지막 전체 gate는 **298 passed / 187.37초 / exit0**(full_verified.log), Ruff check **All checks passed!**, format **67 files already formatted**로 통과했다. 기존232개 회귀 + 신규66개 검사를 실행했다. 이전 중간 전체 실행은296 passed/185.60초, 표현식 수정 후297 passed/193.74초이며 최신 Tab 수정 이전 기록이다. 최종 설치본 경로·해시는 아래와 같다.

## Windows 입력

최신 소스 ConPTY 80×24: Ctrl+Right→D1, Ctrl+G E2→`=B2`+F4+Enter로 `=$B$2`, SUMPRODUCT=110, 정렬 실제 SGR 적용, 빠른 Tab 패킷으로 열1=a AND 열2>1 입력 후 SGR 적용·숨긴 행{1,3}/revision4, Ctrl+Z 필터 복구/revision5, Ctrl+Z 정렬 복구/revision6, Ctrl+Q exit0. native_source_final.json에 실제 입력·출력 청크와 저장 assertion을 기록했다.

자동 ConPTY/Pilot 증거이며 사람의 실제 IME/폰트/화면 승인이나 무손실 전체 화면 녹화로 확대하지 않는다.

## 재현 명령

```powershell
& .\.runtime\python315\python.exe -m pytest -q --basetemp docs/upgrades/evidence_0_3_0/recheck_new
& .\.runtime\python315\python.exe -m ruff check texel tests scripts
& .\.runtime\python315\python.exe -m ruff format --check texel tests scripts
.\build.ps1
```

설치본은 `scripts/verify_distribution.py --package-root <설치 루트> --evidence <새 폴더>`로 실제 CLI/UI/MCP stdio와 값·경로를 검증한다. wheel은 별도의 프로젝트 내부 target에 설치하여 소스 경로가 잘못 import되지 않았는지 확인한다.

## 한계와 보존

사람의 한국어 IME/터미널·폰트/접근성 기기, 장시간/다중 작성자 soak, Linux/macOS 실제 터미널, 특정 AI 호스트 등록은 미검증이다. 수식 진단은 직접 정적 참조이며 최대10,000 수식/200결과, 일반 float 산술과 Excel 전체 객체/VBA/인쇄/비공개 Google 원격 쓰기는 기존 범위와 한계를 유지한다. 전체 행·열 선택도 기존10,000셀 편집 상한을 적용한다.

과거 감사 보고서/evidence와 기존 배포물은 보존한다. Git 저장소가 없으며 커밋/푸시/태그/외부 배포/전역 계정 설정을 수행하지 않았다. 의존성 잠금 버전은 바꾸지 않고 기존 Pydantic을 직접 의존성으로 명시했다. 새 취약점 조회나 전체 Excel 호환을 검증했다고 주장하지 않는다. 독립 리뷰는 한 번 수행했고 후속 수정은 회귀·실제 경로로 확인했으며, 독립 정식 재감사 PASS를 대신하지 않는다.
