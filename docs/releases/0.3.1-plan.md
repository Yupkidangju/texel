# 0.3.1 공개 저장소·자동 릴리스 계획

작성: 2026-10-16 (Asia/Seoul). 근거: 공개 GitHub texel 저장소·커밋/푸시·CI/CD·태그 자동 릴리스·Apache 2.0 사용자 요청. 기존 감사/검증/배포물은 보존한다.

## 계약과 설계

- 저장소: 로그인 계정 Yupkidangju의 공개 `texel`, 기본 main. 이번 요청으로 최초 커밋/푸시/태그/공개 릴리스를 수행한다. 기존 로컬 .git은 커밋/원격이 없다.
- 버전: 유지보수 소스와 신규 공개 패키지 메타데이터/CI를 포함하여 0.3.1. Python >=3.14, native schema 1, MCP39도구/89함수 유지.
- 라이선스: Apache-2.0 원문 LICENSE, `Copyright 2026 yupkidangju@gmail.com`을 LICENSE 적용 안내와 NOTICE에 표시. 의존성 개별 라이선스 보존.
- 배포: 공통 py3-none-any wheel 및 sdist. Windows x64는 기존 공식 embeddable Python 기반 오프라인 portable ZIP도 새로 생성. Linux/macOS/Windows ARM64는 Python 3.14+ wheel 설치 경로이며 독립 실행형·서명·공증 패키지라고 주장하지 않는다.
- CI: Windows 2025 x64 / Windows 11 ARM64 / Ubuntu 24.04 x64·ARM64 / macOS 15 Intel·ARM64에서 Python 3.14 전체 테스트, Ruff, 빌드, 별도 wheel 설치본의 CLI/UI/MCP stdio 검증. Ubuntu x64 Python 3.15 추가. IME/접근성/장시간 실제 장비는 별도 미검증 범위.
- 의존성: 고정 버전 유지, Windows 전용 pywin32에 플랫폼 marker 추가. 설치/테스트 실패를 skip/continue-on-error로 우회하지 않는다.
- CD: v* 태그 push → 버전 일치 → 동일 CI → wheel/sdist·새 Windows portable 빌드/설치 검증 → SHA256SUMS → GitHub Release. 일반 main push/PR은 검증만 한다. PyPI 등록은 범위 밖.
- 권한: 검사/빌드 contents:read, release 단계만 contents:write. 공식 action은 확인한 commit SHA 고정. source allowlist/index를 검토하여 runtime/cache/output/사용자 데이터/비밀정보를 제외한다.
- 실패/복구: 실패 게이트는 게시 차단. 태그/릴리스를 덮어쓰거나 force push하지 않는다. 공개 후 문제는 새 patch로 수정하며 기존 파일/해시를 보존한다.

대안: Windows 전용 유지 대신 공통 wheel+6개 네이티브 CI를 선택. 6개 OS별 독립 실행형은 Python 재배포/macOS 서명/Linux ABI 범위가 추가되므로 이번에는 공통 wheel 설치를 제공한다.

## 순서와 완료 기준

1. 명세/설계·버전/라이선스/README·빌드 안내 동기화.
2. 플랫폼 marker·CI/태그 게이트·패키지 검증 구현. 배포 회귀 및 전체 테스트/Ruff.
3. 공개 source index 파일/크기/비밀 패턴 검토 후 최초 커밋·공개 저장소 생성·main push.
4. 실제 호스팅 CI 7환경 확인. 실패는 원인 수정 후 재실행.
5. v0.3.1 태그 push 후 CD의 실제 공개 Release/파일 다운로드·SHA256 대조.
6. 결과/실행 URL/커밋·태그/자산 해시/지원 검증·한계를 기록하고 필요한 기록 커밋 push.

스킬의 별도 승인 대기보다 사용자 요청과 AGENTS.md의 문서 확정 후 자율 구현 정책을 따른다. GitHub 공개 생성·커밋·태그·푸시·릴리스는 이번 요청으로 승인된 범위다. 과거 감사와 배포물을 정리 명목으로 삭제하지 않는다.

### Windows ARM64 설치 계약 보정

최초 실제 CI에서 cryptography50.0.2가 Windows ARM64 wheel을 제공하지 않고 OpenSSL 개발 환경이 필요한 소스 빌드로 전환됨을 확인했다. PyPI 공식 파일 목록과 upstream 설치 문서로 확인했다. 이번 릴리스는 Linux/macOS ARM64 네이티브를 유지하고 Windows11 ARM64는 x64 Python/portable의 OS 에뮬레이션 경로로 검증한다. 위 최초 6개 네이티브 CI 가정은 이 단락으로 보정한다. 테스트를 제외하거나 의존성을 제거하지 않으며 CI 이름에 Python 아키텍처를 표시한다. Windows ARM64 네이티브는 미지원으로 문서화한다.
