# 0.3.1 공개 배포 결과

작성: 2026-10-16 (Asia/Seoul). 기준: [계획](0.3.1-plan.md). 현재 검증·게시 진행 중이며 아래 결과는 완료 후 확정한다.

로컬 코드: 0.3.1, MCP39도구/89함수, Apache-2.0. 공통 wheel/sdist와 Windows x64 portable 배포. Python 3.14+ 설치가 다른 OS/CPU의 실행 전제다. 원본 감사/과거 배포물은 보존한다.

## 로컬 검증

- 전체 **304 passed / 190.80초**, Ruff check PASS / format **73 files already formatted**. evidence_0_3_1/local_full.log, ruff_check.log, ruff_format.log.
- 태그/제품·패키지 버전/저작권 및 portable ZIP 이름·소스 변조 회귀 5개 추가. 처음의 새 모듈 수집 실패는 개별 기능 실패 증거로 확대하지 않는다.
- wheel/sdist에 LICENSE/NOTICE 원문 및 Apache-2.0 메타데이터 포함, wheel 제품 소스 동일성, 별도 설치본 0.3.1의 CLI/80×24 UI/MCP stdio39·함수89·batch/undo 검사 통과. local_wheel_check_final.log 및 local_wheel_result.json.
- Windows embeddable의 모듈 탐색/pip 부재를 실제 검사에서 발견해 helper의 프로젝트 경로와 uv 대체 설치를 보완했다. 초기 실패 로그도 보존한다.
- 공식 action SHA 고정, actionlint1.7.12 워크플로 검사 통과. 공개 후보 파일의 자격증명 패턴 검사에서 발견 없음. 이 검사는 모든 비밀정보 부재의 증명이 아니다.

GitHub main/태그 검증과 공개 자산 다운로드 대조는 진행 중이다.

최초 호스팅 CI 38853333878은 새 checkout에 .cache 부모가 없는 상태에서 pytest --basetemp .cache/pytest-ci가 mkdir(parents=False)를 호출해 실패했다. Linux3.14 로그는 127 passed/177 fixture errors이며 제품 동작 실패와 구분한다. 로컬에서는 기존 .cache가 있어 드러나지 않았다. CI 초기 단계에서 작업 디렉터리를 명시적으로 생성하고 새 커밋으로 7환경 전체를 다시 검증한다. 실패 로그는 ci_initial_linux14.log에 보존한다.

Windows ARM64의 cryptography50.0.2 설치는 OpenSSL 개발 환경 부재로 실패했다(ci_initial_windows_arm.log). 공식 PyPI에는 win_amd64만 있고 win_arm64 wheel은 없다. 계획의 최초 네이티브 가정을 명시적으로 보정하여 Windows11 ARM64는 x64 Python 에뮬레이션으로 검증한다. Linux/macOS ARM64 네이티브 지원은 유지한다. Windows ARM64 네이티브 바이너리/개발 도구 설치를 제공한다고 주장하지 않는다.

예정된 CI: Windows 2025 x64, Windows 11 ARM64, Ubuntu 24.04 x64·ARM64, macOS 15 Intel·ARM64의 Python3.14, Ubuntu x64 Python3.15. 전체 테스트/Ruff/빌드/격리 wheel CLI/UI/MCP stdio 검사. 이 목록은 현재 실행 성공을 뜻하지 않는다.

미검증: 실제 사용자 한국어 IME/폰트/접근성 장비/장시간 soak. CI의 Textual 입력과 Windows 과거 ConPTY를 사람의 장비 검증으로 확대하지 않는다. macOS 앱 서명·공증, Linux/ARM64 독립 실행형, PyPI 게시는 이번 범위 밖이다.
