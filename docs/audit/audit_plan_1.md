# Texel 전체 기능 감사 계획 1

작성: 2026-10-11 (Asia/Seoul). 요청: 선 그리기, 우클릭 메뉴, 파일 읽기 실패를 포함한 전체 기능 재점검 및 코더 전달용 리포트. 기준: AGENTS.md, spec.md, designs.md, AI_AUDIT_DOC_STANDARD.md, AI_CODING_STANDARD.md, AI_IMPLEMENTATION_DOC_STANDARD.md.

## 목적과 범위

0.2.0의 문서상 기능을 실제 공개 입력 경로와 결과에 대조한다. 구현 적합성, 디버그/품질, 보안의 세 pass를 분리하고 하나의 보고서로 통합한다. 제품 소스, 기존 테스트, 설정, 구현 문서는 변경하지 않는다. 감사 문서와 독립 재현 스크립트/fixture/log만 `docs/audit/`에 추가한다. 기존 작업 및 배포물은 보존한다.

## 실행 순서와 결정

1. 런타임/의존성, 문서, 코드, 기존 테스트, 배포물의 현 상태를 확인하고 제품 파일 SHA256을 보존한다.
2. 기존 전체 pytest 및 Ruff를 현재 설치된 Python으로 실행해 기초 상태를 기록한다. 준비 스크립트로 의존성을 재설치하지 않는다.
3. 우선 신고 경로: 실제 키/좌표/선택 위젯 조작 → 모달 → 변경 → 저장/재열기 → 화면 결과를 추적한다. 기존 테스트가 내부 상태만 설정하는 부분은 별도 공개 입력 재현으로 보완한다.
4. 명령 카탈로그 전체와 계산/편집/구조/서식/분석/교환/저장/MCP/배포를 기능표에 매핑한다. 정상/실패/경계 경로를 실행하고 코드를 대조한다.
5. 가능하면 현재 소스와 portable의 Windows ConPTY 입력 경로를 실행한다. 자동 터미널 증거와 사람이 보는 실제 IME/폰트/기기 검증은 구분한다.
6. 발견 항목마다 ID, 심각도, 재현, 기대/실제, 정확한 코드 위치, 수정 방향, 재감사 기준을 작성한다. 보고서는 `docs/audit/audit_report_1.md`에 저장한다.

## 완료 기준과 한계

- 기존 테스트/검사 결과와 신규 재현 결과를 구분하며 실패를 숨기지 않는다.
- 카탈로그의 모든 기능을 검증표에 포함하고, 실행 검증/정적 추적/미검증을 명시한다. 기능 존재만으로 정상 판정하지 않는다.
- 보고서와 실행 가능한 재현 자료를 코더가 사용할 수 있다. 수정은 이번 감사 범위 밖이다.
- 소스/기존 테스트/설정의 지문을 전후 비교하여 변경하지 않았음을 확인한다.
- 사람의 한국어 IME, 터미널 설정별 직접 조작, 접근성 기기, 장시간 작업, 다른 OS, 비공개 Google 계정 및 원격 쓰기는 직접 검증할 수 없으면 미검증으로 기록한다.
- 감사는 새 사용자 데이터 또는 유료 서비스를 만들지 않는다. 외부 공식 자료는 버전 의존 동작이나 보안 경계 확인에 필요한 부분만 조회한다.
